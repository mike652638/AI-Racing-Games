# src/audio/

## 职责

程序化音频合成模块（无外部音频资源）：为游戏提供引擎音效（`engine.ts`）、雨声/碰撞环境音效（`engine.ts`，M11 F4）、BOOST 氮气音效（`engine.ts`，H2）与背景音乐（`music.ts`）多路 WebAudio 输出。引擎音效将车辆速度比映射为引擎声的音高/音量/滤波参数；雨声以循环白噪声 + 带通滤波模拟环境底噪、碰撞音以短噪声 burst 模拟冲击（H6 起碰撞强度按速度比缩放增益，高速撞击更响）；BOOST 音以 sawtooth 200→600Hz 线性扫频 + 增益包络模拟氮气喷射（H2）；**M15 起新增漂移摩擦声（`DriftSound`，bandpass 噪声循环 + 强度调制）与轻量胎噪（`TireSound`，lowpass 噪声循环）**；背景音乐以 16 步循环序列调度 chiptune 风格的合成音色。各子模块相互独立、互不依赖，仅共享由外部注入的同一个 `AudioContext` 实例与可选输出节点（M10 P6 起经构造第二参注入 `masterGain` 主音量节点；M12 G7 起分轨为 `musicGain`/`sfxGain` 注入）。纯参数计算与音符换算逻辑被抽取为可单测的纯函数，合成器类只负责 WebAudio 副作用。

## 设计

- **依赖注入**：`AudioContext` 由 `GameLoop` 惰性创建（首次按键交互，满足浏览器自动播放策略）后作为构造参数注入 `EngineSound` / `MusicPlayer` / `RainSound` / `CollisionSound` / `BoostSound` / `DriftSound`（M15） / `TireSound`（M15），各实例共享同一上下文，避免多 context 的资源开销，也便于外部统一管理用户手势后的 `resume()`。**M10 P6 输出节点注入**：各构造均以可选第二参 `output: AudioNode = ctx.destination`——`EngineSound` 的 `gain.connect(output)`、`MusicPlayer` 的音符/踩镲 `connect(output)`、`RainSound`/`CollisionSound` 的 `gain.connect(output)`、`BoostSound` 的 `osc.connect(gain).connect(output)` 改连注入节点；`GameLoop` 以 `masterGain`（主音量节点，`gain.value = this.volume`）为 output 注入全部实例，实现暂停菜单音量 slider 的统一调节；默认参数保证旧调用（不传第二参）零改动。
- **噪声合成音效（M11 F4）**：`RainSound`——2s 白噪声 buffer（`Math.random` 填充）循环播放 → bandpass 800Hz（Q=1）→ gain 0.05 → output；`start()` 幂等（`started` 标志防重复建源、`ctx.resume()` + gain `setTargetAtTime` 渐入）、`stop()` 渐出并 `source.stop()`、`isPlaying()` 暴露播放状态（debug hook / 冒烟断言用）。`CollisionSound`——0.15s 白噪声 burst → lowpass 300Hz → gain 0.25 → output；`play()` 每次重建 BufferSource 触发单次冲击（`source.start(0)`），80ms 内重复触发跳过（`lastPlayTime` 对比，防连续碰撞刷屏），`count` getter 暴露播放次数；**H6 强度参数**：`play(volume = 1)` 以 `gain.gain.value = 0.25 × clamp(volume, 0.4, 1)` 缩放（volume 为碰撞强度 0-1 速度比，高速撞击更响）。
- **BOOST 氮气音效（H2）**：`BoostSound`——每次 `play()` 重建 osc/gain 节点（无防刷屏，`count` getter 递增暴露播放次数）；sawtooth 频率 `setValueAtTime(200, t)` → `linearRampToValueAtTime(600, t + 0.25)` 线性扫频，增益包络 `0 →(0.02s) 0.15 →(0.25s) 0`，`osc.stop(t + 0.26)`；`osc.connect(gain).connect(this.output)` 链式连接注入输出节点。防刷屏由调用方承担——`GameLoop` 以 `boostActive` 边沿检测（本帧激活且上帧未激活）触发，天然每次激活只响一次。
- **漂移摩擦与胎噪音效（M15）**：`DriftSound`——2s 白噪声循环 → bandpass（700-2000Hz，Q=2）→ gain（≤0.3）→ output；`start()`/`stop()` 幂等（仿 RainSound，stop 渐出防爆音）、`setIntensity(speedRatio, steerAbs, wet)` 经 `computeDriftSoundParams`（强度 = 0.6×速度比 + 0.4×转向，湿滑频率 ×0.75 变闷、增益 ×0.8 压低）用 `setTargetAtTime`（τ=0.05s）平滑调制滤波器频率与增益。`TireSound`——lowpass 1500Hz 噪声循环、构造即启动（gain 0 静音，仿 EngineSound 持续输出模式），`setLevel` 经 `computeTireSoundParams`（电平 = 0.6×速度 + 0.3×转向 + 湿滑 0.1，封顶 `TIRE_GAIN_MAX=0.02` 不喧宾夺主）平滑设置增益。两者均注入 sfxGain 分轨，受暂停菜单音效/主音量控制；每帧驱动开销 ~0.03μs。
- **纯函数与副作用分离**：`computeEngineParams(speedRatio)`（速度比 → 频率/增益）、`noteToFreq(name)`（音符名 → 频率）、`tickMsForBpm(bpm)`（BPM → 8 分音符时长）均为纯函数，无 WebAudio 依赖，可直接单测；M12 G6 起 `MusicPlayer` 的调度逻辑同样纯函数化——`stepEvents(step)`（16 步中某一步的事件映射：`bass = BASS_LINE[Math.floor(step/4) % 4]`、`melody = step % 2 === 0 ? MELODY_LINE[Math.floor(step/2) % 8] : null`、`hat = step % 4 === 0`）与 `nextStep(step) = (step + 1) % 16`，`playStep` 改调 `stepEvents` 分发、`schedule()` 用 `nextStep` 推进（行为逐字节一致）；类仅封装振荡器/增益/滤波等副作用。
- **合成音色**：引擎声采用双锯齿波（detune 0/7）+ 低通滤波（800Hz）叠加模拟引擎轰鸣；音乐采用方波低音 + 锯齿波旋律 + 白噪声踩镲（Am-F-C-G 和声进行，120 BPM）；BOOST 音采用锯齿波 200→600Hz 线性扫频模拟氮气喷射。
- **平滑过渡**：引擎声参数更新用 `setTargetAtTime` 指数逼近（时间常数 0.05s），避免参数跳变产生爆音；BOOST/踩镲等一次性节点则用 `linearRampToValueAtTime`/`exponentialRampToValueAtTime` 包络收尾。
- **RAF 驱动调度**：`MusicPlayer` 用 `requestAnimationFrame` 以 30Hz 固定步长驱动，替代 `setInterval`（更抗节流）；`dt` 上限 0.1s，防止页面后台恢复时突发调度。
- **前瞻调度（lookahead scheduling）**：每次调度把音频时钟未来 0.2s 内的音符一次性排入 `ctx.currentTime` 时间轴，保证节奏精度，不受 RAF 抖动影响。
- **延迟初始化**：音频在用户首次按键交互时才创建（满足浏览器自动播放策略），由 `main.ts` 惰性构建。

## Flow

1. `GameLoop` 捕获首次键盘事件（`onKeyDown`，M7 起音频惰性创建已从 main.ts 下沉至此）→ 创建 `AudioContext` → 先建 `masterGain = ctx.createGain()`（`gain.value = this.volume`，连 `ctx.destination`）→ **M12 G7 起分轨**：`musicGain`（`gain.value = this.musicVolume`，M12 音乐分轨音量）与 `sfxGain` 各连 `masterGain`——`new MusicPlayer(ctx, musicGain)` + `start()`、`new EngineSound(ctx, sfxGain)`、`new RainSound(ctx, sfxGain)` + `new CollisionSound(ctx, sfxGain)`（M11 F4 环境音效走音效轨）、**`new BoostSound(ctx, sfxGain)`（H2 氮气音效走音效轨）**、**`new DriftSound(ctx, sfxGain)` + `new TireSound(ctx, sfxGain)`（M15 漂移/胎噪走音效轨）**（各实例共享同一 ctx）。
2. 主循环每帧调用 `engineSound.setSpeedRatio(race.carState.speed / carConfig.maxSpeed)`：速度比经 `computeEngineParams` 纯函数换算为频率/增益，再用 `setTargetAtTime` 平滑更新双振荡器频率、滤波截止频率与主增益。
3. `MusicPlayer.start()` 记录起始时间并启动 RAF 循环；`tick` 回调按 30Hz 固定步长累积时间，累积满一个步长即调用 `schedule()`。
4. `schedule()` 执行前瞻调度：持续把 `nextTime`（BPM 推导的 8 分音符时长递增）之前 0.2s 内的步进交给 `playStep(step, when)`，步进索引经 `nextStep(step)` 0-15 循环推进（M12 G6）。
5. `playStep` 经 `stepEvents(step)` 纯函数分发（M12 G6）：低音每 4 步、旋律每 2 步、踩镲每 4 步，每个音色通过独立 osc/gain 节点在指定时间 `when` 起止并指数衰减，避免残留。
6. **环境音效驱动（M11 F4 / H6）**：帧循环 `PHASE_RACING` 块内按 `Math.floor(player1.raceTime / WEATHER_CYCLE_SECONDS) % 3 === 2` 判定雨段——雨段 `rainSound.start()` / 非雨段 `rainSound.stop()`（类内幂等，每帧调用）；`updateCollisions` 后对比 `race.collisionCount` 增长 → **H6 起 `collisionSound.play(impact)`（`impact = max(P1/P2 速度比)`，取双玩家较快者，单屏 P2 speed=0 自然取 P1，高速撞击更响）**，`lastCollisionCount` 快照在 `resetRace` 时同步归零。
7. **BOOST 音效驱动（H2）**：帧循环按 `boostOn = effInput1.boost === true || effInput2.boost === true`（G4 蓄力/消耗后的有效输入）与 `boostActive` 上一帧快照做边沿检测——本帧激活且上帧未激活 → `boostSound.play()`（类内无防刷屏，靠边沿检测天然只响一次）；`boostActive = boostOn` 每帧更新，`resetRace` 时归零。
8. **漂移/胎噪驱动（M15）**：帧循环 `updateFrame`（frame-update.ts）内——非 RACING 分支 `driftSound?.stop()` + `tireSound?.setLevel(0, 0, false)`（暂停/菜单/结算无声）；RACING 分支在玩家物理更新后（driftState 最新）按 `race.player1/2.driftState.active` 判定（分屏取剧烈一方），强度取双玩家车速比与转向绝对值最大值、湿滑沿用既有 `wet`（与雨声/雨天物理同源）：漂移激活 `start()` + `setIntensity(speedRatio, steerAbs, wet)`，否则 `stop()`；胎噪每帧 `setLevel`。GameLoop 仅在 startGame 惰性创建音频时实例化并注入 sfxGain，未创建时 null 安全 no-op。
9. 调试钩子 `window.__gameDebug.audioState / musicState / volume / rainPlaying` 暴露运行时状态（`rainPlaying` 为 `rainSound?.isPlaying() ?? false`，M11 F4 加），供 bot 自动化验证读取。

## Integration

- Consumed by:
  - `src/game/game-loop.ts`：惰性创建 `AudioContext` 与 `masterGain` 主音量节点（`gain.value = this.volume`），**M12 G7 分轨**——`musicGain`（`musicVolume`，初值 0.8）与 `sfxGain` 各连 `masterGain`，`MusicPlayer(ctx, musicGain)` / `EngineSound(ctx, sfxGain)` / `RainSound(ctx, sfxGain)` / `CollisionSound(ctx, sfxGain)` / `BoostSound(ctx, sfxGain)`（H2）与 `DriftSound(ctx, sfxGain)`/`TireSound(ctx, sfxGain)`（M15）注入；每帧以 `speed / maxSpeed` 驱动 `setSpeedRatio`；帧循环雨段判定驱动 `rainSound.start()/stop()`、`collisionCount` 增长触发 `collisionSound.play(impact)`（H6：impact 为双玩家速度比取较快者）、**`boostActive` 边沿检测触发 `boostSound.play()`（H2：任一玩家 boost 激活且上帧未激活）**；`setVolume(v)` / `setMusicVolume(v)` 分别同步 `masterGain.gain.value` / `musicGain.gain.value` 并持久化 localStorage（key `outrun-pseudo3d-volume` / `outrun-pseudo3d-music-volume`）；`window.__gameDebug` 暴露 `audioState`/`musicState`/`volume`/`rainPlaying` 供自动化验证
  - `tests/unit/engine-audio.test.ts`：单测 `computeEngineParams`、`MIN_FREQUENCY`、`MAX_FREQUENCY`、M10 P6「EngineSound 输出注入」2 用例（不传 output 连 `ctx.destination` 向后兼容；传 output 时 `gain.connect` 目标为注入节点）、M11 F4「RainSound」用例（构造未播放、start 幂等不重建源、stop 后 isPlaying false）、「CollisionSound」用例（play 触发且 80ms 内重复触发被跳过；**H6 `play(volume)` 按强度缩放增益：play(0.5) → 0.25 × clamp(0.5, 0.4, 1) = 0.125、play(0.2) 低于下限 clamp 到 0.4 → 0.1**）与 **H2「BoostSound」用例（play 触发扫频振荡器：ramp 含起始 200 与目标 600；每次调用重建节点无防刷屏、count 递增）**；mock 的 `createOscillator` 返回可链对象（`connect` 返回 `{ connect }`）以支持 `osc.connect(gain).connect(output)` 链式调用
、`tests/unit/drift-tire-audio.test.ts`（M15：`computeDriftSoundParams`/`computeTireSoundParams` 纯函数钳制/湿滑系数、DriftSound/TireSound 构造输出注入、start/stop 幂等、setIntensity/setLevel 调制目标断言）与 `tests/unit/frame-update-audio.test.ts`（M15：漂移激活/未激活/分屏 P2/雨天 wet 接线、胎噪逐帧调制、非比赛阶段静音、null/undefined 安全 no-op）
  - `tests/unit/music.test.ts`：单测 `noteToFreq`、`tickMsForBpm`、`BASS_LINE`、`MELODY_LINE`，以及 M12 G6「调度纯函数」4 用例（`stepEvents(0/1/2)` 事件映射、`nextStep` 0→1 / 15→0 回绕）
- Depends on:
  - `Web Audio API`（`AudioContext`/`OscillatorNode`/`GainNode`/`BiquadFilterNode`/`AudioBufferSourceNode`），运行时浏览器环境提供
  - `requestAnimationFrame` / `performance.now()`（页面全局计时）
  - 外部注入 `AudioContext`（不自行创建，无对其他 src 模块的编译期依赖）
