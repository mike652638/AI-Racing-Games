## 二、测试结果总览

### 2.1 问题统计

| 严重度     | 数量 | 分类                                             |
| ---------- | ---- | ------------------------------------------------ |
| P0（阻塞） | 9    | 开始按钮被榜单卡遮挡/不可达（跨 9 个场景）       |
| P1（重要） | 1    | 320×568 极窄屏主标题与副标题重叠                 |
| P2（一般） | 12   | 菜单光晕与开始按钮重叠、榜单多行折叠、副标题重叠 |
| P3（建议） | 若干 | 详见「其他改进建议」                             |

> 数据来源：`docs/menu-test/overlap-analysis.json`（逐场景几何重叠计算）与 `docs/menu-test/issues-raw.json`（规则化问题清单）。

### 2.2 关键结论

**核心缺陷（P0）**：「开始游戏」按钮在**内容超高（需滚动）的所有分辨率**下，会与榜单卡片发生几何重叠，导致主 CTA 被榜单卡覆盖、无法直接点击或视觉上被遮挡。该问题在桌面 1280×720、平板横屏 1024×768、所有手机横屏（812/667/740）、手机竖屏（540/390/375）共 9 个场景稳定复现，重叠面积占榜单卡面积的 11%–21%。

**根因**：`#start-btn` 的 `position: sticky; bottom: 8px` 设计（M-1 引入，意图是内容超高时主 CTA 保底可见）。当 `.menu-content` 内容高度超过视口（`scrollHeight > clientHeight`）时，sticky 按钮吸在视口底部，恰好叠在内容流末尾的榜单卡上方。该设计与"榜单卡紧跟其后"的内容顺序冲突，未预留 sticky 按钮的专属空间。

## 三、问题详细清单

### P0 — 阻塞级问题

#### P0-1 「开始游戏」按钮被榜单卡遮挡（9 个场景）

| 场景                 | 视口     | 被遮挡榜单 | 重叠面积 | 占榜单比 |
| -------------------- | -------- | ---------- | -------- | -------- |
| 桌面基线             | 1280×720 | 漂移榜单   | 5294 px² | 21%      |
| 平板横屏             | 1024×768 | 漂移榜单   | 3151 px² | 16%      |
| 手机横屏             | 812×375  | 漂移榜单   | 3072 px² | 13%      |
| 手机横屏             | 667×375  | 漂移榜单   | 3072 px² | 14%      |
| 手机横屏             | 740×360  | 漂移榜单   | 2798 px² | 12%      |
| 手机竖屏             | 540×960  | 漂移榜单   | 7280 px² | 15%      |
| 手机竖屏（竖屏继续） | 540×960  | 对局战绩   | 8193 px² | 19%      |
| 手机竖屏（竖屏继续） | 390×844  | 漂移榜单   | 5697 px² | 17%      |
| 手机竖屏（竖屏继续） | 375×667  | 赛道最佳   | 3600 px² | 11%      |

- **表现**：`#start-btn` 计算样式 `position: sticky; bottom: 8px`，在内容超高时浮于视口底部，视觉上压住第二张或第三张榜单卡（如 1280×720 时按钮矩形 `y:628→680`，漂移榜单卡 `y:569→658` 及 `y:589→678` 与之相交）。
- **影响**：
  1. 用户无法直接点击「开始游戏」按钮（榜单卡覆盖其上，命中点落到榜单卡上）；
  2. 榜单卡内容（榜单名次）被按钮遮挡，读榜不完整；
  3. 视觉上按钮悬浮在卡片之上，破坏 dashboard 整体感（M20 榜单容器优化的预期效果被破坏）。
- **证据**：`docs/menu-test/desktop-1280x720.png`、`mobile-landscape-812x375.png`、`mobile-portrait-540x960.png`、`overlap-analysis.json`。

**修复方向建议**：

1. **给 sticky 按钮预留占位**：`.menu-content` 底部增加与按钮等高的 `padding-bottom`（如 `calc(52px + 16px)`），使内容滚动到底时按钮不再覆盖榜单；
2. **改用非 sticky 方案**：移除 `position: sticky`，依赖容器滚动自然呈现按钮（配合 M-1 原本就有的 `overflow-y: auto`），内容超高时按钮随内容滚动到最后自然出现；
3. **若保留 sticky**：将按钮置于 `.menu-content` 之外（如 `#start-screen` 底部独立 fixed 层），与滚动内容彻底分离，互不遮挡。

### P1 — 重要级问题

#### P1-1 极窄屏（320×568）主标题与副标题重叠

- **表现**：320×568 下主标题矩形底部 `y=55`，副标题顶部 `y=0`，垂直重叠 55px 以上。副标题实际被压在主标题之下或与之交叠。
- **影响**：极窄屏用户看到标题区文字互相叠影，品牌信息不可读。
- **证据**：`docs/menu-test/mobile-portrait-320x568.png`、`issues-raw.json`。
- **修复方向**：`@media (max-width: 390px)` 分支已缩小 `--title-fs`，但 `.title-sub` 的负上边距（`margin: -8px 0 28px`）在极窄屏未收敛，可对该分支显式将副标题负边距归零或改用 `margin-top` 正值。

### P2 — 一般级问题

#### P2-1 菜单底部光晕（.menu-sun）与「开始游戏」按钮几何重叠（12 个场景）

- **表现**：`.menu-sun` 的光晕矩形（约 162×162px）在几乎所有场景（桌面 1280/1366/1600/1920、平板、全部手机）与 `#start-btn` 区域相交。如 1280×720 时光晕 `y:502→664`，按钮 `y:628→680`，重叠约 36px。
- **影响**：按钮视觉被暖色光晕"晕染"，虽不影响点击，但降低了按钮文字对比度与可识别性。
- **证据**：`issues-raw.json` 12 条 P2 记录。
- **修复方向**：`.menu-sun` 在内容超高场景下应随内容滚动（已是 `#start-screen` 背景层，但光晕半径 `box-shadow: 0 0 32px 10px` 过大），可降低光晕透明度或上移光晕位置。

#### P2-2 竖屏榜单卡分 3 行堆叠，加剧内容超高

- **表现**：540×960、390×844、320×568 竖屏下，3 张榜单卡（赛道最佳/漂移榜单/对局战绩）纵向堆叠为 3 行，每张约 93–97px 高，加工具栏共占约 350px。
- **影响**：竖屏空间本就有限，榜单单列堆叠进一步压缩赛道卡与按钮的可视区域，是 P0-1 内容超高的重要推手。
- **证据**：`mobile-portrait-540x960.png`、`tablet-portrait-768x1024.png`。
- **修复方向**：竖屏下榜单卡可改为折叠默认（master toggle 默认收起）或更紧凑的单行条目展示，降低默认高度。

#### P2-3 1280×720 内容超高但首屏不提示可滚动

- **表现**：1280×720 下 `.menu-content` `scrollHeight=842 > clientHeight=720`，内容超高需滚动；但首屏底部提示「空格键开始 · 1-9 / 方向键 切换赛道」在 `y:803→823`，**超出视口**，需滚动才可见。
- **影响**：用户首屏看不到操作提示，且不明确下方还有榜单/按钮内容（虽然 sticky 按钮保底可见）。
- **证据**：`sup-clean-1280x720.png`（按钮 bottom=680 已近视口底，提示文字 803+ 不可见）。
- **修复方向**：桌面 1280×720 是常见笔记本分辨率，应确保首屏容纳全部核心交互（赛道卡+按钮），或显式给出滚动提示。

#### P2-4 平板竖屏（768×1024）不显示旋转提示但布局偏松

- **表现**：768×1024（平板竖屏）下 rotate-hint 不显示（符合 `(orientation: portrait) and (max-width: 1024px)` 但宽度恰为 1024 边界值的情况需注意），菜单以竖屏姿态居中，赛道卡 2 列、榜单 3 行。
- **影响**：可接受，但 1024 边界值与手机竖屏行为不一致，建议统一阈值语义。

### P3 — 交互与细节改进建议

1. **rotate-hint 全屏遮罩层级**：手机竖屏首次进入时，rotate-hint（建议横屏 + 竖屏继续）全屏覆盖菜单。测试发现点击「竖屏继续」后菜单正常，但**旋转提示遮罩与菜单背景透明度处理**可优化（当前遮罩不透明，看不到背后菜单，无法预判竖屏布局）。
2. **榜单 master toggle 语义**：交互测试通过——初始「收起」、点击变「展开」且卡片高度 89→56px、再点恢复 89px、`aria-expanded` 同步翻转。但收起态下 `cardsHeight=56px` 仍占一行（工具栏+卡片头），若目标是"完全折叠省空间"可进一步将 `.lb-card-body` 折叠为 0。
3. **键盘焦点顺序**：Tab 焦点实测可从赛道卡逐张遍历（track-option 均 tabindex=0），但**焦点落点与视觉层级不总是匹配**——低高度横屏下 Tab 可能跳过被隐藏的预览/副标题而直达榜单卡，建议验证 9 卡焦点环完整。
4. **开始按钮 loading 态无视觉占位**：`#start-btn.loading` 置灰 0.55 透明度，但点击后若启动耗时，按钮尺寸不变，用户无进度反馈，可增加微交互（如按钮内 spinner）。
5. **菜单光晕与选中赛道预览光的叠加**：切换赛道时 `.track-option.selected` 的脉冲光晕与中央 `#track-preview` 的轨迹光晕在 812×375 等低高度下距离较近，视觉上有轻微双光源冲突（M20 已部分收敛，可复查）。

## 六、结论

主菜单在常规桌面分辨率（1366/1600/1920）下整体表现良好，9 赛道网格、榜单 dashboard、键盘/触屏交互均正确。但存在一个**高优先级布局缺陷**：`#start-btn` 的 sticky 保底设计在内容超高时与榜单卡几何重叠，覆盖 9 个常见场景（含桌面 1280×720 基线、全部手机横竖屏），直接影响主 CTA 可达性与榜单可读性，建议优先修复。次要问题包括极窄屏标题重叠、菜单光晕干扰按钮、竖屏榜单堆叠加剧超高。修复后建议在 1280×720、812×375、540×960 三个代表分辨率上复测，并以 `docs/menu-test/overlap-analysis.json` 的"重叠面积 = 0"作为通过标准。
