# AI-Racing-Games 运行时实测与视觉验证报告

## 执行摘要

本次实测基于 Vite 开发服务器（npm run dev，端口 5173）下 1280×720 桌面视口的浏览器（agent-browser + Chromium 无头），覆盖单屏/分屏/热座/挑战四种模式与 9 条赛道中的关键代表（经典、沙漠挑战、峡谷疾驰夜晚、森林穿梭、海岸公路），结合 DOM 快照、像素采样、debug API 与暂停菜单检查，发现 **2 个核心 bug、4 个高频 UX 问题、6 个中频 UI/UX 体验项、5 个微优化建议**。整体运行稳定、视觉差异化显著、环境色板准确，操作提示与热座结算优于预期。最大问题是 **minimap canvas 内容渲染为空（100% 透明像素）**，以及 **玩家车出界后无法回到路面（疑似卡死）**，以及 **开局几乎必有"碰撞 ×1"提示（车流与玩家初始位置重叠）**。

## 一、测试环境与方法

- **运行时**：本地 Vite dev server（Node.js 22 + Vite），`npm run dev` 启动后 HTTP 200
- **浏览器**：agent-browser 驱动的 Chromium 无头实例，1280×720 桌面视口
- **驱动手段**：键盘事件通过 `dispatchEvent(KeyboardEvent)` 注入（agent-browser press 是单击，无法模拟"持续按住油门"），玩家车在前进段持续触发 `keydown`、停止段触发 `keyup`
- **辅助检查**：`window.__gameDebug` API（19 个 getter：phase、selectedTrack、collisions、driftActive、split、hotseatPlayer、volume、rainPlaying 等）、`document.getElementById('hud-minimap').getContext('2d').getImageData` 像素采样、agent-browser snapshot -i 元素引用、agent-browser screenshot 全画面截图
- **测试范围**（34 张截图，存于 `docs/screenshots/shot-01..shot-34.png`）：
  - 单屏：经典赛道、沙漠疾驰（挑战模式）、峡谷疾驰（夜晚）、森林穿梭、海岸公路
  - 分屏：经典赛道（左右双世界）
  - 热座：S 弯挑战（P1 黄色 vs P2 绿色两回合）
  - 完赛：海岸公路（NEW RECORD + 漂移 0）+ S 弯挑战热座（P2 更快 + 连胜 1）
  - 菜单展开：赛道最佳 / 漂移榜单 / 对局战绩三个面板

## 三、核心 bug（必须修复）

### BUG-1：minimap canvas 完全透明 / 渲染异常

**严重程度**：高（功能性问题，玩家无法看到赛道进度）

**复现路径**：
1. 任意赛道单屏模式
2. 长时间保持 W 加速、撞车或出界
3. 观察右上角 #hud-minimap 元素（位置 1124,183，110×110）
4. debug 采样：`document.getElementById('hud-minimap').getContext('2d').getImageData(...)` —— `TOTAL_NONTRANSPARENT=0`（100% 透明像素）
5. `canvas.toDataURL('image/png').length` 仅 858 字节（几乎为空 PNG）

**根因猜测**（基于 src/ui/minimap.ts 与 src/game/frame-render.ts 源码）：
- minimap 实例在 GameLoop 构造时创建，绑定初始 trackContext
- frame-render.ts 检测 `minimap.trackContext !== race.tracks[0]` 时重建实例
- 当玩家车出界、车流反复碰撞、LAP 推进过程中，race.tracks[0] 引用可能因某种 race condition 未正确替换新 TrackContext，导致 minimap 持有的旧 trackContext 与新 trackContext 不相等但被某种 short-circuit 跳过重建，最终 update(cameraZ) 内部 `this.points.length === 0` 早返回不绘制
- 也可能是 canvas 的 clearRect 在 update 之前被外部误清

**现象截图**：docs/screenshots/shot-23-racing-stuck.png、shot-24-still-racing.png、shot-26-resumed.png、shot-27-debug.png 右上角均可见一个**空心蓝灰色矩形框**——这是 minimap 容器 CSS box-shadow 或父元素 #hud 的样式残留，canvas 内容透明。

**预期**：minimap 始终显示赛道轨迹折线 + 起点金色小方块 + 玩家位置亮黄圆点（与 src/ui/minimap.ts 第 88-134 行 update 方法描述一致）。

**建议**：检查 frame-render.ts 第 124 行 `if (minimap.trackContext !== race.tracks[0])` 比较的稳定性（可能引用比较失败）、minimap 实例销毁时的 canvas 清理（避免幽灵 canvas）、以及 pause 时 clearRect 后 resume 时未恢复 update 调用的时序。

### BUG-2：玩家车出界后无法回到路面（疑似卡死）

**严重程度**：中-高（影响玩家体验，但不阻断完赛路径）

**复现路径**：
1. 海岸公路或任何赛道
2. 高速（>250 km/h）时按 A 或 D 长按转向
3. 玩家车冲出路面进入草地/海面
4. 松开方向键、尝试转向回路面 —— **玩家车无法从草地/海面回到路面**（玩家车被弹出赛道外很远）

**根因猜测**（基于 src/physics/car.ts 的 updateCar）：
- 出界时 carState.position 被钳制到赛道边缘，但没有强制 z 推进
- 玩家车在草地上既无推进速度（减速），也无路径跟随（无 z 累积），导致**状态完全冻结**
- 同时 cameraZ 不再增加，赛道滚动停止，远景不移动 → 玩家视觉上感觉"卡住"

**现象验证**（实测日志）：
- 出界前：LAP 1/2，时间 0:08.441，速度 320 km/h
- 出界后：速度从 320 km/h 降到 102 km/h 后稳定、时间从 0:08.441 → 0:27.216 累加但变慢、最终时间 2:00.871 后**停止推进**（尽管 phase 仍 'racing'）

**预期**：出界应有明确的"减速 → 推回路面"或"重置到上一个 checkpoint"逻辑，让玩家能继续游戏。

**建议**：检查 car.ts 的出界钳制逻辑，考虑：出界后强制 z -= 一定距离（推回赛道），或显示明显"撞墙"特效 + 自动重置。

## 四、高频 UX 问题（每次游戏都能观察到）

### UX-1：开局几乎必有"碰撞 ×1"

**复现频率**：实测 6 次开局（单屏经典、单屏沙漠挑战、单屏峡谷、单屏森林、单屏海岸、热座 S 弯）**全部出现开局"碰撞 ×1"**，部分开局直接"碰撞 ×2-3"。

**根因猜测**（基于 engine/traffic.ts 与 createTraffic）：
- 车流生成时按 z 递增顺序插入，前方车流与玩家初始 z=0 之间距离过近
- 部分车流被放置在玩家车正前方 50-100 单位（约 0.25-0.5 秒距离），按 maxSpeed 320 km/h 即 89 m/s 在 < 0.5s 内必撞
- 实测截图：shot-04、shot-09、shot-13、shot-16、shot-18、shot-30 均显示玩家车正前方近距离出现一辆大型黄色卡车

**预期**：开局至少 2-3 秒内不应有车流在玩家前方 200 单位以内（约 2-3 秒距离），让玩家能"起飞"。

**建议**：
- createTraffic 默认从 z=200 开始生成首辆车
- 或按赛道类型生成"起飞安全区"（plains 长直道 vs S 弯短急弯）
- 配合"开局 2 秒碰撞免疫"或"碰撞强度 < 阈值不计"逻辑

### UX-2：HUD 速度大字（M16 引入）过大略显突兀

**实测**：高速段速度显示"320"字体几乎与玩家车等高，对周围场景造成视觉压力。在 shot-04、shot-09 中可见大数字紧贴视口右侧。

**建议**：将大数字字号从当前的 56-64px 适当缩小（如 44px），或加半透明黑色描边/阴影以减少视觉权重。

### UX-3：菜单无当前模式视觉提示

**实测**：打开 `?challenge=1`、`?split=1`、`?hotseat=1` 时菜单画面与默认单屏几乎无区别：
- 单屏 P1 选中态：黄色边框
- 分屏 P1 选中态：绿色边框（仅此一处差异）
- 热座 P1 选中态：黄色（与单屏相同，**用户无法区分自己处于热座模式**）
- 挑战模式：与单屏完全相同（**无法区分**）

**建议**：在菜单顶部加一个"模式徽章"显示当前 URL 模式（"挑战模式 60 秒刷分"、"热座 · 回合制"、"分屏 · 双人同屏"），或在副标题下加一行小字说明。

### UX-4：完赛画面"完赛！"标题被滚动条遮挡

**实测**：热座 P2 完赛画面（shot-31-hotseat-final.png）顶部"完赛！"标题被浏览器右侧滚动条遮挡，仅能看到下半部分的"赛！"字样。

**建议**：结算面板使用 fixed positioning + 居中，避免页面整体高度超出视口。或在 panel 容器外加 overflow: hidden。

## 五、中频 UI/UX 体验项

### UX-5：菜单三个"展开"面板无互斥折叠 / 撑高视口

**实测**：三个面板（赛道最佳 / 漂移榜单 / 对局战绩）可同时展开，导致"开始游戏"按钮被推到视口外，需要向下滚动才能看到（shot-32、shot-33、shot-34）。

**建议**：实现"互斥展开"——点击一个面板时自动折叠其他面板。或限制最多同时展开 1 个。

### UX-6：回主菜单按钮文字被光晕遮挡

**实测**：单屏完赛画面"回主菜单"按钮周围红色光晕较强（shot-21），"回到主菜单"5 个字被发光晕染难以辨认。

**建议**：减小按钮 glow 半径（box-shadow 从当前 30px 降至 15px）或提高按钮文字对比度（白色文字 + 黑色描边）。

### UX-7：菜单中央激光/光圈动效过亮

**实测**：菜单中央的赛道预览"S 弯挑战"标识周围有红色激光动效（shot-10、shot-32、shot-33），但亮度较高，遮挡周围文字。

**建议**：将激光动效透明度从当前 0.8 降至 0.5，或限定在中心 80px 半径内。

### UX-8：菜单模式无 P1/P2 标签 / 分屏无明显标识

**实测**：分屏模式左右两个赛道仅靠位置和颜色（P1 黄 vs P2 绿）区分，但 HUD 文字颜色统一（白色），未见"P1"/"P2"字样标签。

**建议**：HUD 顶部加 "P1" / "P2" 小字标签（M9 codemap 提到此功能但实测未体现），或在速度数字旁加 P1/P2 颜色边框。

### UX-9：夜晚车灯光晕过大，影响玩家车体辨识

**实测**：峡谷疾驰夜晚赛道（shot-13、shot-14），玩家车头灯形成大团亮黄色光晕（半径约屏幕 1/6），玩家车体（红色矩形）被光晕完全笼罩，难以辨识车辆细节。

**建议**：减小车灯 bloom 半径（M11 引入的 headlights arc radius 从当前 30+ 降至 15）或降低 alpha。

### UX-10：路灯在路面上方而非路外

**实测**：森林穿梭（shot-16）、海岸公路（shot-18）、峡谷疾驰（shot-13）多个赛道，路灯出现在**路面上方**而非路面两侧。

**根因猜测**：路灯 sprite 投放时 x 偏移使用了相对窄的边界值，在弯道上与路面边界相交。

**建议**：检查 sprite-draw.ts 中路灯 sprite 的 x 投放范围（建议 ±ROAD_WIDTH × 1.8 而非 ±1.4），或在弯道内侧剔除路灯 sprite。

## 六、低频优化建议

### UX-11：仙人掌形状抽象

**实测**：沙漠疾驰的仙人掌（M17 新增）形状为绿色十字/风车，与"沙漠仙人掌"的常见认知有差距（shot-08、shot-09）。

**建议**：保留 M17 差异化设计意图，但考虑增加一个"垂直主干 + 横向两臂"的分支形状变体，让仙人掌辨识度更高。

### UX-12：漂移得分多次为 0

**实测**：单屏海岸公路 P1 完赛漂移 0、热座 S 弯 P1/P2 完赛漂移 0（shot-21、shot-29、shot-31）。可能原因：玩家车按 W 单击保持直线行驶未触发自动漂移；S 弯赛道太短（2 圈 56 秒）来不及累计漂移分；或漂移激活阈值过高。

**建议**：增加调试日志（player1.driftScore 实时 HUD 显示），或在结算画面增加"漂移命中率"指标（尝试漂移次数 vs 成功次数）。

### UX-13：对局战绩"暂无对局记录"但热座 P1 vs P2 已进行

**实测**：热座 P1 完赛（0:56.790）+ P2 完赛（0:27.025），菜单"对局战绩"仍显示"暂无对局记录"（shot-32）。

**建议**：热座模式的胜负结果应记录到对局战绩（M11 codemap 提到热座也记录对局），或明确说明热座不算对局（仅分屏算）。

### UX-14：菜单赛道卡片选中态激光动效

**实测**：菜单赛道卡片选中态周围有激光描边动效（shot-32、shot-33），与中央赛道预览的激光动效视觉冲突。

**建议**：调整选中态激光动效的颜色或与中央预览做时序错开，避免两层激光重叠。

### UX-15：HUD km/h 单位与数字字号差距过大

**实测**：速度"320"是大字号（约 56px），"km/h"是小字号（约 14px），二者比例约 4:1，视觉层级过于悬殊。

**建议**：将 km/h 单位字号适度提升（24px），与数字形成 2.3:1 的层级。

## 七、性能与稳定性观察

1. **PWA 离线**：未实测（dev mode 无 service worker，需 build 后验证）
2. **帧率**：肉眼观察 60fps 流畅，无明显卡顿
3. **音频**：测试中未启动 WebAudio（agent-browser 无音频输出），需要人工听感测试
4. **存档兼容性**：热座 P2 完赛后菜单"赛道最佳"正确显示"3. S 弯挑战 P1 0:56.790 · P2 0:27.025"——验证 save.ts 的 P1/P2 双维度存档工作正常
5. **M16 操作提示**：挑战模式"WASD/方向键 驾驶"提示出现在游戏开始时——验证 copy.ts 同源化有效

## 十、局限性
