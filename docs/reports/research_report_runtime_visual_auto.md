## 执行摘要

本报告基于对 `http://localhost:5173/`（Vite dev 服务器）的一轮无人值守自动化测试：通过 browser-use 自动化浏览器完成页面加载检查、控制台/网络检查、核心游戏流程全链路验证（菜单→开始→倒计时→行驶→暂停/恢复→完赛→回主菜单），并抽验分屏、热座、挑战三种模式入口。全程采集 10 张截图留证（`docs/screenshots/auto-*.png`）。

**总体结论：当前运行时状态可玩，未发现 P0/P1 阻塞问题，零控制台错误/告警。** 主要发现为 1 个 P2 游戏性问题（开局车流与玩家出生位置重叠导致「碰撞 ×1」，静止时会被连续撞击）、2 个 P3 建议项与若干自动化测试条件限制。桌面主流程与三种扩展模式均验证通过。

## 问题列表

### 问题 1：开局车流与玩家出生位置重叠（游戏性/流程逻辑）——✅ 已修复（2026-08-05 同日）

- **严重级别**：P2（一般）
- **复现路径**：任意模式开始比赛，开局 1s 内观察 HUD；或开始后不按任何键静止等待
- **实际表现**：开局即出现「碰撞 ×1」；静止不动 10s 内累计「碰撞 ×3」（auto-02）——车流 NPC 主动撞上静止玩家，每次触发减速与碰撞音
- **根因修正（确定性探测 + e2e 实测后确认）**：双重机制——① 部分种子下首车生成在 z<80 窗口与玩家重叠；② **主因**：环形赛道上后方车流（classic seed 777 为 z=87053）在 ≈1.9s 即环绕穿越出生点，此时正值倒计时（≈2.9s），静止玩家必被撞（探测脚本实测 first collision = 1.93s）
- **修复实现（双保险）**：
  1. `TRAFFIC_SPAWN_SAFE_ZONE = 1600`（engine/traffic.ts）：`createTraffic` 新增尾参，把出生窗口 [0, 1600) 内的车重映射至窗口外（rnd() 消费顺序不变，确定性保持；缺省 0 保 bot 基线与既有单测不变）；game/track-context.ts 创建/重建车流时启用。
  2. `RACE_START_GRACE = 5`（shared/constants.ts）：`updateCollisions` 按各玩家个人计时门控——raceTime < 5s 免疫车流碰撞，覆盖倒计时与开局短窗口；热座回合重置天然重新生效；单测置 raceTime ≥ 阈值直接验证碰撞机制。
- **验证锚点**：traffic.test.ts 5 用例（窗口排除/确定性/rnd 顺序不变/不叠车）+ track-context.test.ts 2 用例（9 赛道初始车流与 refreshTraffic 均出窗）+ collision.test.ts 保护期用例 + constants.test.ts 注册表 + **e2e 回归**（开赛 3.5s 内 `__gameDebug.collisions === 0`，桌面/移动双 project 通过，实测 18 passed）。
- **相关截图**：auto-02-countdown.png（修复前碰撞 ×3 证据）

### 问题 2：倒计时画面无法自动化留证（测试条件限制，非游戏缺陷）——✅ 已由 e2e 断言覆盖

- **严重级别**：P3（建议）
- **实际表现**：高帧率 canvas 动画期间截图工具两次 15s 超时；倒计时覆盖层仅能经 DOM 校验确认（可见、提示文案在位）
- **后续**：已补 Playwright e2e 断言（覆盖层可见 + 数字 ∈ {3,2,1} + 结束后隐藏，桌面/移动双 project 通过）；视觉样式仍**需人工复测**
- **行为修正说明**：本报告初稿曾断言「倒计时期间 HUD 计时恒为 0:00.000」，经 e2e 实测修正——**计时/物理随开赛同步启动，与倒计时覆盖层共存**（raceTime += dt 于 RACING 帧无条件累计，属设计行为）；「倒计时期间冻结计时」若成为需求需另行改造

### 问题 3：移动视口关键 UI 未验证（测试条件限制）

- **严重级别**：P3（建议）
- **实际表现**：当前浏览器自动化工具不支持视口 resize，无法切换 812×375 移动横屏；竖屏窄视口的「请旋转设备」提示层在前一轮会话中已观察到正常触发
