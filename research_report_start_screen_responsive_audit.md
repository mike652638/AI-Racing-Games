## 三、问题深入分析

### 3.1 P0-1：移动横屏「我的榜单」隐形（核心问题）

**布局数据**（812×375 实测）：

```
.menu-content: scrollHeight = 419px, clientHeight = 225px（bottom:150px 让位给 footer）
.leaderboard-section: top = 253px, bottom = 413px（完全超出可视区）
.menu-footer: top = 309px（固定底部）
可滚动？scrollTop 可设为 200+（可滚），但无任何视觉提示
```

**根因链条**：

1. `.menu-content` 为 `position:absolute; bottom:150px` 的滚动容器，可视高仅 225px；
2. 3×3 赛道网格 + 标题已占满可视区，榜单被推到容器下方；
3. 滚动条样式为 8px 半透明 accent 细条（webkit 定制），在深色背景上几乎不可见；
4. 滚动容器内无「下方还有内容」的渐变遮罩/阴影提示 → 用户不会滚动 → 榜单区功能性地"消失"。

**影响**：移动端玩家看不到自己的最佳成绩/漂移榜单/对局战绩，且由于空态文案也在其中，无法感知该功能存在。这是移动端最严重的问题。

**建议方案**（按优先级）：

- **方案 A（推荐）**：低高度视口（如 `@media (max-height: 480px)`）下将赛道网格压缩为更紧凑的行距/卡高，使榜单至少露出标题行（约 40px），形成"可滚动"的心理暗示；
- **方案 B**：`.menu-content` 底部加 24-32px 渐变遮罩（`linear-gradient(transparent, rgba(11,5,24,0.9))`），滚动容器底部出现"内容渐隐"效果，天然提示可滚动（同时遮挡滚动中露出 footer 的内容）；
- **方案 C**：隐藏细滚动条改为 `scrollbar-width: none` + 触屏滑动（移动端系统本身支持惯性滚动），避免"看得见摸不着"的细条干扰。

### 3.2 P1-1/P1-2：桌面小高度下榜单被裁切

1280×720（720p 笔记本）与 1024×768（老式笔记本/小屏）是真实用户占比不小的视口，当前榜单均需滚动才能完整查看：

- 1280×720：`bottom:150px` 预留 footer 后可视区仅 570px，内容 625px，榜单底部 31px 被裁；
- 1024×768：内容 783px vs 可视 618px，榜单整体在可视区外。

根因与 P0-1 相同（内容超高时依赖内部滚动），但桌面端滚动条可见性稍好（observer 判定 1024×768 滚动条"明显"）。

**建议**：

- 收紧 720p 高度下的纵向间距（标题 margin、网格行距、榜单 section margin 共可释放 40-60px）；
- 或将 `bottom:150px` 在低高度视口下调至 120px（footer 实际渲染高度约 100-110px），扩大可视区。

### 3.3 P2-2：竖屏旋转提示层遮挡内容

提示层本身是模态覆盖，遮挡属预期；但 4 个竖屏视口均遮挡到赛道卡片第 3 行（9/9 卡中的 3 张），360×800 下连「我的榜单」标签都被遮。建议：

- 提示层内容（图标+文案+双按钮）垂直居中偏上，将卡片第 3 行留出；或
- 提示层改为半透明面板 + 可点击"继续浏览菜单"的降级入口（当前「竖屏继续」已承担此责，可考虑将其上移到提示层中部，减少底部遮挡）。

### 3.4 P2-4：副标题对比度

`#start-screen .title-sub` 使用浅灰/低透明度文字，在深色渐变背景上对比度低于 WCAG AA 建议（约 4.0:1 以下）。建议提升至 `rgba(255,255,255,0.85)` 或加 `text-shadow: 0 1px 4px rgba(0,0,0,0.8)`（标题区已有类似阴影可对齐）。

## 五、测试过程备注（工程经验）

1. **并行命令竞争 daemon**：agent-browser 的 `set viewport` 是会话级状态，并行 bash 调用会互相抢占视口，导致截图"串台"（如 812×375 截图实际渲染成竖屏弹窗态、1920×1080 按 6 的截图丢失榜单区）。**教训**：视口切换与截图必须串行执行；本次已用 clean 重拍 + DOM 数据交叉验证排除误判。
2. **DOM 实测 > 视觉直觉**：observer 对 1280×720 的初步判断"应显示中央预览"经 CSS 断点核对后确认是预期行为（`min-width:1280px and min-height:700px` 恰好覆盖 1280×720）；最终结论均以 `eval` 实测数据为准。
3. 本轮未改动任何源码，纯测试与审计。

## 六、结论

#start-screen 在大屏（1920×1080 起）与标准桌面（1366×768 以上）表现优秀：布局完整、背景层赛道预览联动正确、交互可用、无 JS 错误。**主要问题集中在低高度视口**：移动横屏（812-926 × 375-428）下榜单区完全隐形且无滚动引导（P0），1280×720/1024×768 桌面下榜单底部被裁切（P1）。建议优先实施第 1-3 条必做优化，可在不改动任何 JS/HTML 的前提下，仅靠 CSS 媒体查询解决 90% 的问题。
