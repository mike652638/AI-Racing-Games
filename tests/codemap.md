# tests/

## Responsibility

质量验证层。通过四层自动化测试基建保障 OutRun 伪 3D 赛车游戏各模块的正确性，并作为里程碑验收的门禁（typecheck + test + bot + e2e 全绿）：

- `tests/e2e/`：**M16** 新增 Playwright 视觉回归（`npm run test:e2e`，桌面 1280×720 + 移动横屏 812×375 双 project，`playwright.config.ts` 自动拉起 vite dev server）。覆盖报告（docs/reports/research_report_runtime_testing.md）修复点的防回归：菜单红色光晕不遮挡赛道卡片（P1-1）、标题与副标题不叠影（P1-2）、天空无高频条纹（P0-1，canvas 像素级 maxDelta < 60）、倒计时提示由 copy.ts 常量填充（与 README 同源）、热座 P1 HUD 标签、移动端横屏开始按钮在视口内（等 1.2s 菜单入场动画避免 translateY 偏移误判；桌面 project 跳过移动端断言）。
- `tests/unit/`：白盒单元测试（Vitest，共 47 个 `.test.ts`、681 个用例）。对 `src/` 下各模块的纯函数与状态机做行为验证，覆盖伪 3D 投影、路面分段几何、赛道生成与管理（M9 起 9 条赛道含难度星级，M11 起含夜晚赛道 `timeOfDay` 标记）、车辆运动学（M12 含雨天 wet 抓地力/制动衰减与氮气 boost 加速）、漂移（含 M10 连击/倍率与得分 clamp、M13 H1 scoreMultiplier 挑战加成透传）、碰撞（含 M16 碰撞红闪反馈状态机）、bot 决策、跑圈模拟、UI 格式化与 HUD（含单屏 P2 BEST、热座玩家标签、M10 漂移连击 COMBO 显示、M11 得分 MAX 标记、M12 挑战模式倒计时 challengeTimer 兼容）、文案常量（M16 copy.ts 与 README 同源防漂移）、存档（含胜场统计、漂移 TOP10 排行榜、M10 各赛道 BEST 汇总、M11 分屏对局 TOP10、M13 H4 排行榜条目 combo 连击字段保留与混存兼容）、输入映射（M12 含 boost 键）、音频合成（含 M10 EngineSound 输出注入、M11 RainSound/CollisionSound 噪声音效、M12 MusicPlayer 调度纯函数 stepEvents/nextStep、M13 H2 BoostSound 扫频与 H6 CollisionSound 强度分级、**M15 DriftSound/TireSound 漂移胎噪与帧驱动接线**）、光照（含阴天 overcast、M9 白天天空恒蓝、M10 雨天 raining、M11 夜晚 night 色板、**M17 环境差异化 environment**）、场景生成（含 M17 差异化景物形状）、游戏阶段与玩家状态、常量注册表（含车流常量与 M12 CHALLENGE_SECONDS/BOOST 系列）、车流密度配置与避让 AI（M12 含 shiftDir 变道方向）、虚拟摇杆 reset、玩家车精灵（P0 drawPlayerCar：laneOffset 平移/steer 倾斜/夜间车灯/BOOST 尾焰）、菜单赛道缩略图（M17 track-preview SVG 生成），以及 Renderer / GameLoop 两个状态型模块的集成验证（含热座模式、9 赛道选择、暂停菜单音量/重开/触屏按钮、M12 挑战模式计时、G7 音乐/音效分轨音量、M11 夜晚车灯 arc 与变道转向、M13 H3 夜间车尾灯 fillRect 增量、M13 H2 boost 粒子 arc 增量、雨滴离屏 drawImage 平铺、M13 H4 漂移榜「连击 x」后缀）；**M15 新增 game 层 4 模块独立单测（mode-strategy 四模式路由/finish-accounting 结算记账/frame-update 帧更新挂钩/frame-render 渲染分支）与音频接线测试（drift-tire-audio 纯函数+类调制/frame-update-audio 帧驱动静音与调制）**；**M18 新增 road-surface（路缘柔和过渡：近处 4 档细节色/远端自动跳过/确定性）与 terrain-draw（沙丘 sin 折线/海面波浪随 time 漂移/plains 零绘制/rock 不受影响）两渲染模块独立单测**。
- `tests/bot/`：黑盒集成验收脚本。用 `simulateLaps` 驱动 bot 在真实赛道上自动跑圈，输出圈速/违规 JSON 报告，并以进程退出码（0/1）判定通过/失败。
- `tests/__mocks__/`：Canvas 测试替身基建。`canvas.ts` 提供可记录调用次数与实参的 mock canvas / ctx，支撑 Renderer 与 GameLoop 的"渲染输出确实发生、稳定且坐标对齐"类断言。

## Design

- **纯函数优先**：被测模块多为无副作用的纯函数（`project`、`roadColors`、`formatSpeed`、`noteToFreq`、`updateLighting`、`projectSmoke`、`updateDrift` 等），测试直接断言输入→输出映射，无需 mock 框架。
- **依赖注入 mock（分层替身）**：
  - `fakeStorage()`：`save.test.ts` 用内存 `Map` 实现模拟 Web Storage（getItem/setItem/removeItem/clear/key/length），验证存档读写、覆盖策略与 `storage=null` 容错。
  - `StubElement` / 对象字面量元素：`game-loop-integration.test.ts` 的 `createElementStub()`、`hud.test.ts` 的 `createMockHudElements()`、`track-manager.test.ts` 的 DOM 依赖 mock，仅暴露被测代码触达的属性（`textContent`/`hidden`/`classList.toggle`/`appendChild`/`addEventListener`），用 `vi.fn()` 记录调用。
  - `stubEnvironment(search = '', initialStorage?)`：`game-loop-integration.test.ts` 通过 `vi.stubGlobal` 替换 `window`（记录 keydown 监听器供 `fireKey` 触发）、`document`（`getElementById` 按 id 返回元素替身，`finish-*-2` 与 `finish-drift-winner`/`finish-wins` 初始 `hidden=true` 以锚定结算面板显隐缺陷）、`requestAnimationFrame`（记录回调供 `driveFrames` 驱动真实帧循环）、`AudioContext`（EngineSound 所需最小 WebAudio 替身），实现真实 GameLoop 的集成冒烟。search 参数兼容 string|boolean：`''`（单屏）/ `'?split=1'`（分屏）/ `'?hotseat=1'`（热座），布尔 `true` 等价 `'?split=1'`；`fireKey(code, shiftKey?)` 触发键盘事件（shiftKey 供 P2 的 Shift+1-9 键位）；`debugValue(key)` 读取 `window.__gameDebug`（installDebugHook 注入的运行时状态，供断言当前回合/玩家/P2 世界车流 z/主音量 volume）；P6 起扩展——`initialStorage?: Record<string, string>` 尾参（传入时挂载 Map 实现 fakeStorage 并 `vi.stubGlobal('localStorage')`，save.ts getStorage 双重检查需全局 + window 都满足，不传时保持既有 null 降级语义）、`StubElement` 增 `value: string` 字段（音量 slider 0-100）与记录式 `addEventListener`（`_listeners` Map 保存回调）、`fireElementEvent(id, type)` 触发元素事件（pause-volume input / pause-restart click 等）。
  - canvas mock（`createMockCanvas`）：见下。
- **canvas mock 调用记录机制**：`__mocks__/canvas.ts` 覆盖 renderer 实际调用的全部 ctx 方法（fillRect/beginPath/moveTo/lineTo/closePath/fill/stroke/save/restore/translate/rect/clip/drawImage/arc/setTransform/getImageData，P5 补 stroke 记录、M18 补 ellipse 记录）与 GameLoop 用到的元素方法（addEventListener/appendChild/setPointerCapture）；`__calls` 记录各方法调用次数、`__args` 记录每次调用的实参数组（二者一一对应），支撑「渲染输出稳定（每帧绘制次数恒定）」「确实发生绘制（fill/fillRect 计数增长）」「坐标整数对齐（rect/translate 参数取整）」「雨滴离屏双幅 drawImage 平铺（帧内零 stroke）」「夜晚车灯 arc 增量」断言。
- **确定性种子测试**：对种子化生成器（`createTraffic`、`createRoadsideSprites`、`generateMountainProfile`）验证同 seed 输出一致、不同 seed 输出不同，支撑 bot 可复现校验。
- **多帧状态机测试**：`drift`、`collision` 等状态机测试以固定 `dt` 循环调用多次，模拟帧推进验证状态转换、冷却衰减与粒子生命周期。
- **集成式端到端模拟**：`simulate.test.ts` 与 bot 脚本通过 `simulateLaps` 串联 bot 决策 → 车辆物理 → 赛道分段 → 违规检测，验证整条跑圈链路（含弯道、环形回绕、步长敏感性、maxSteps 截断）。
- **集成冒烟（真实主循环）**：`game-loop-integration.test.ts` 构造真实 `GameLoop`，用 rAF 回调驱动帧循环 + 模拟键盘事件，验证 menu→racing→paused→finished 阶段流转、分屏模式（`?split=1`）、热座模式（`?hotseat=1`，交棒与输入路由、P2 世界车流回合推进、胜场统计行）、P1/P2 独立选赛道、9 赛道选择（Digit1-9 与 Shift+1-9）、修饰键回归（Shift 单独按下不触发开始）、HUD 点亮、结算面板填充、漂移竞速横幅与双人完赛、`#drift-top` 榜单渲染、P3 `#best-summary` 各赛道 BEST 汇总（占位与存档注入两态）、M11 F2 `#match-top` 分屏对局 TOP10（双完赛后非占位）、P6 暂停菜单（PAUSED 按 KeyR 回菜单、`pause-restart` click、`pause-volume` input 更新主音量经 `debugValue('volume')` 断言）、M11 F3 触屏暂停（`pause-btn` click 进入暂停、`pause-resume` click 恢复、PAUSED 时 joystick.reset 被调用）、M11 F4 雨段环境音（驱动至 ~100s `debugValue('rainPlaying')` true、阴/晴段 false）、M12 G1 挑战模式（计时刷新、超时 finished 且结算显示挑战文案）、M12 G7 分轨音量（`pause-music-volume`/`pause-sfx-volume` input 更新 musicVolume/sfxVolume 并持久化）、M13 H4 漂移榜连击渲染（注入含 combo 的条目后 `#drift-top` 含「连击 x」后缀、旧条目不追加），并含视觉缺陷回归（P2 结算行显隐、`finish-wins` 初始隐藏）；「分屏双人完赛」用例（4000 帧双人模拟）testTimeout 放宽 15000ms（M9 记录为既有脆弱性：默认 5000ms 下偶发超时）。
- **常量注册表测试**：`constants.test.ts` 对 `src/game/constants` 的漂移/碰撞/渲染/路面几何/车流常量做值断言（防魔法数字回潮），并校验 `road-geometry` 兼容导出 `DRAW_DISTANCE` 与真源一致。
- **回归锚点**：`traffic-render`（车流投影尺寸上限）、`sprites`（景物投影高度上限）、`game-loop-integration`（缺陷①数字键误开始 / 缺陷②P2 赛道名隐藏 / C3 双人结算 P2 行可见）等用例锚定历史缺陷，防止回退。
- **局部辅助构造器**：每个测试文件内定义 helper（`state()`、`car()`、`trafficCar()`、`straightCtx()`、`createHarness()`、`createMockHudElements()`、`createElementStub()`）构造被测输入，保持用例简洁；`tests/helpers/`（`track.ts`、`sprites.ts`）存放从 src 迁移的仅测试使用导出（`createDefaultTrack`、线性版 `spritesInRange`），供多个测试文件共享。
- **中文行为规格**：用例以中文命名描述行为场景（如「弯道前超速时刹车」「分屏模式下 P2 与车流碰撞」），测试本身兼具行为文档作用。

## Flow

1. `npm run typecheck`（tsc --noEmit）：静态类型检查，先于一切验证。
2. `npm run lint`（eslint .）：代码规范检查。
3. `npm test`（vitest run）：执行 `tests/unit/*.test.ts` 全部 47 个单测文件（681 个用例）。
4. `npm run bot`（tsx tests/bot/run-bot.ts）：M13 H8 起为全赛道矩阵回归——遍历 `TRACK_DEFS` 全部 9 条赛道（含 canyon/alpine 夜间赛道），每条按自身 `def.laps` 圈数调用 `simulateLaps(createTrackFromDef(def), createCarConfig(), createBotConfig(), { laps: def.laps })`，输出每条赛道的 JSON 报告（trackId、name、laps、finished、lapTimesSec、totalTimeSec、avgSpeed、violations、offRoadTimeSec）；判定逻辑：全部赛道 `finished === true && violations <= 3` 时打印「✅ bot 跑圈通过（9 条赛道全部完成，0 违规超标）」并以退出码 0 结束，否则打印「❌ bot 跑圈失败」退出码 1。
5. `npm run build`（tsc --noEmit && vite build）：发布构建验证，每里程碑最后执行。
6. `npm run test:e2e`（playwright test）：**M16** 视觉回归，CI 独立 job（e2e）执行，失败时上传 `test-results/` 产物。

## Integration

- Tests 覆盖 src 全部六大目录：
  - `src/engine`：projection、road-geometry、road-surface（M18 路缘柔和过渡）、track、tracks、traffic、traffic-render、sprites、scenery、terrain-draw（M18 地形装饰）、smoke-render、lighting、player-car（P0 玩家车精灵）、renderer（renderer-state）
  - `src/physics`：car、drift、input
  - `src/ai`：bot、simulate
  - `src/ui`：format、gamestate、save、joystick、hud
  - `src/audio`：engine（engine-audio、M15 drift-tire-audio）、music（music 调度、M15 frame-update-audio 帧驱动接线）
  - `src/game`：collision/state、constants、phase（phase-logic）、player-state、track-context（含车流密度）、track-manager、track-preview（M17 菜单赛道缩略图 SVG）、game-loop（单测 + 集成冒烟，含热座与 9 赛道）、M15 mode-strategy / finish-accounting / frame-update / frame-render 四模块独立单测
- `tests/__mocks__/canvas.ts` 被 `renderer-state.test.ts` 与 `game-loop-integration.test.ts` 复用，支撑渲染器与主循环的绘制断言。
- Depends on: `vitest`（单测运行器）、`tsx`（bot 脚本执行器）、`tests/helpers/`（track/sprites 测试辅助：迁移自 src 的 `createDefaultTrack` 与线性版 `spritesInRange`）、`src/ai/simulate`（simulateLaps 跑圈引擎）、`src/engine/track`（createStraightTrack（@deprecated 仅测试使用）/ createTrack / createSmoothTrack）、`src/engine/tracks`（TRACK_DEFS / createTrackFromDef）、`src/physics/car`（createCarConfig / updateCar）、`src/ai/bot`（createBotConfig / decideBotInput）、`src/game/game-loop`（GameLoop / updatePlayerFrame）、`src/game/track-context` / `src/game/track-manager`（赛道上下文与管理）。
